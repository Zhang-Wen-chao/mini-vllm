HTTP **401** 和 **403** 都表示“请求被拒绝”，但原因不同：

## 1. HTTP 401 Unauthorized：未认证

**401 表示：你还没有证明“你是谁”。**

服务器认为请求缺少有效的身份认证信息，或者认证失败了。

常见场景：

- 没有登录就访问需要登录的接口
- Token 过期
- Token 无效
- 用户名或密码错误
- 没有携带 `Authorization` 请求头

例如：

```http
GET /api/profile HTTP/1.1
Host: example.com
```

如果用户未登录，服务器可能返回：

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer
```

客户端看到 401 后，通常会：

- 提示用户登录
- 重新获取 Token
- 刷新 Token
- 再次发起请求

简单理解：

> **401：请先证明你是谁。**

---

## 2. HTTP 403 Forbidden：无权限

**403 表示：服务器知道你是谁，但你没有权限做这件事。**

也就是说，用户可能已经成功认证了，但当前身份不允许访问该资源或执行该操作。

常见场景：

- 普通用户访问管理员接口
- 用户没有某个资源的访问权限
- 角色权限不足
- 被系统策略禁止访问

例如：

```http
GET /api/admin/users HTTP/1.1
Host: example.com
Authorization: Bearer <valid-token>
```

如果 Token 有效，但用户不是管理员，服务器可能返回：

```http
HTTP/1.1 403 Forbidden
```

客户端看到 403 后，通常不应该反复重新登录，因为问题不是“没认证”，而是“没权限”。

简单理解：

> **403：我知道你是谁，但你不能做这件事。**

---

## 核心区别

| 状态码 | 含义 | 是否已认证 | 客户端通常怎么做 |
|---|---|---|---|
| 401 | 未认证或认证失败 | 否 | 登录、刷新 Token、重新认证 |
| 403 | 已认证但无权限 | 通常是 | 提示无权限，不应盲目重试认证 |

---

## 一个直观例子

假设有一个接口：

```http
GET /api/admin/settings
```

### 情况一：用户未登录

请求：

```http
GET /api/admin/settings
```

没有 Token。

服务器返回：

```http
401 Unauthorized
```

意思是：

> 你还没登录，请先登录。

---

### 情况二：用户已登录，但是普通用户

请求：

```http
GET /api/admin/settings
Authorization: Bearer <valid-user-token>
```

Token 有效，但用户不是管理员。

服务器返回：

```http
403 Forbidden
```

意思是：

> 你已经登录了，但你没有管理员权限。

---

## 一句话总结

> **401 是“你没登录或登录无效”，403 是“你登录了但没权限”。**
