KV cache 是 Transformer 自回归解码时用来缓存历史 token 的 Key 和 Value 的机制。

在生成第 \(t\) 个 token 时，模型需要让当前 token 的 Query 与之前所有 token 的 Key 做注意力计算，并用对应的 Value 加权求和：

\[
\text{Attention}(Q_t, K_{1:t-1}, V_{1:t-1})
\]

如果没有 KV cache，每生成一个新 token，都要重新计算前面所有 token 的 Key 和 Value，甚至重新做一遍注意力计算。  
有了 KV cache，就可以把之前 token 的 \(K\) 和 \(V\) 保存下来，每步只计算当前新 token 的 \(Q, K, V\)，然后把新的 \(K, V\) 追加到缓存中。

它能加速的原因是：

1. **避免重复计算历史 token 的 K/V**  
   自回归解码是逐 token 生成的，历史 token 的表示不会变，因此它们的 Key 和 Value 可以复用。

2. **每步只处理新 token**  
   第 \(t\) 步只需要计算新 token 的 Query，并与缓存中的历史 Key/Value 做注意力，而不是重新计算整个前缀序列。

3. **降低推理计算量**  
   不用 cache 时，每步都要对越来越长的前缀重新计算；用 cache 后，计算量主要来自当前 token 与历史 K/V 的注意力，整体推理效率更高。

简单说：  
**KV cache 通过缓存历史 token 的 Key 和 Value，让自回归解码每步只计算新 token，从而避免大量重复计算，加速生成过程。**  
代价是会增加显存占用，因为需要保存越来越长的 K/V 缓存。
