HTTP **401** 和 **403** 都表示“请求被拒绝”，但原因不同：

## 1. HTTP 401 Unauthorized

**含义：未认证 / 身份未验证。**

服务器认为你还没有提供有效的身份凭证，或者凭证无效。

常见场景：

- 没有登录
- Token 过期
- 密码错误
- API Key 缺失或无效
- Basic Auth 用户名密码错误

典型响应头：

```http
WWW-Authenticate: Bearer
```

这个头会告诉客户端：你需要用什么方式重新认证。

例子：

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer
```

客户端通常应该：

- 提示用户登录
- 刷新 Token
- 重新携带认证信息请求

---

## 2. HTTP 403 Forbidden

**含义：已认证，但没有权限。**

服务器知道你是谁，但你不被允许访问这个资源。

常见场景：

- 普通用户访问管理员接口
- 用户没有某个资源的权限
- IP 被禁止
- 角色权限不足
- 访问被策略拒绝

例子：

```http
HTTP/1.1 403 Forbidden
```

客户端通常不应该再尝试登录，因为问题不是“你是谁”，而是“你没有权限”。

---

## 核心区别

| 状态码 | 含义 | 是否知道用户身份 | 是否应该重新认证 |
|---|---|---|---|
| 401 | 未认证 | 不知道或无法确认 | 是 |
| 403 | 无权限 | 通常知道 | 否 |

简单理解：

- **401：你还没证明你是谁。**
- **403：我知道你是谁，但你不能访问。**

---

## 举例

假设有一个接口：

```http
GET /admin/users
```

### 情况一：未登录

```http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer
```

意思是：请先登录。

### 情况二：已登录，但是普通用户

```http
HTTP/1.1 403 Forbidden
```

意思是：你登录了，但你不是管理员，不能访问。

---

## 一个常见误区

`401 Unauthorized` 这个名字容易误解。

它更准确的意思其实是：

> **Unauthenticated**，未认证。

而 `403 Forbidden` 才是：

> **Authenticated but not authorized**，已认证但无权限。
